# V6：长期目标 Token 与可靠性驱动的持续 Query

日期：2026-10-11。承接 [V5](RESEARCH_V5_20261010.md)，保留 D0、D2、Query v1/v2 的原始 checkpoint 与输出。本记录中“已验证”只指实际完成的代码或实验；性能结论以完整评估结果为准。

## 迁移依据与结构

参考 [ChronoTrack 论文](https://arxiv.org/abs/2604.13789)、[memory_encoder.py](https://github.com/ujaejoon/ChronoTrack/blob/main/models/ChronoTrack/memory_encoder.py)、[transformer.py](https://github.com/ujaejoon/ChronoTrack/blob/main/models/ChronoTrack/transformer.py) 和 [ChronoTrack_task.py](https://github.com/ujaejoon/ChronoTrack/blob/main/tasks/ChronoTrack_task.py)。借鉴的是少量前景 Token 的递归交叉注意力更新、当前观测读取长期记忆，以及训练时的时间一致性与多样性约束；未照搬其单目标 GT 初始化、点云前景 mask 或 Memory Cycle Consistency Loss。

`src/inframot3d/perception/long_term_query_feedback.py` 在现有在线 Query Bank 基础上为每个目标增加 4×64 长期 Token 和确认次数。目标的预测框中心、方向建立 BEV 局部坐标；两层 Token→局部观测交叉注意力、自注意力和 FFN 递归更新记忆。Query 先读取 Token，再读取当前局部 BEV；位置、速度、存在置信、位置不确定性、漏检次数、当前/历史特征一致性和当前特征强度共同决定局部反馈强度。首次无历史输出严格等于原 BEV；跨序列或超时间间隔重置。在线出生、关联和消失仍只依赖模型预测，不读取 GT 或未来帧。

V5 Query v2 有 192388 个参数，V6 Query 模块有 377543 个参数。与 ChronoTrack 的单目标 32×128 Token 不同，这里每帧最多同时维护 64 个目标，因此先使用 4×64 Token；Token 数量不是已调优结论。当前在线关联成本仍沿用 V5 的位置与单 embedding，长期 Token 直接用于检测前读取和身份监督，尚未直接用于关联成本。

`scripts/research_v6/train_long_term_query.py` 从 V5 attention v2 最优权重初始化匹配参数，新增 Token 层，并联合更新 Query 网络、BEV backbone 与 CenterHead；冻结原 3D 提取器和 BEV BatchNorm 统计。连续序列训练采用 6 帧截断 BPTT。GT Track ID 仅用于训练时预测 Query 的同目标跨帧对比约束；重复 ID 的 `0066` 不参加身份监督。额外采用轻量 Token 正交惩罚作为多样性代理，不把它称为 ChronoTrack 的 cycle loss。

## 训练与验证

- Fold A：18 条训练序列、5 条留出序列；原训练侧划分不变。
- 计划 12 epoch，Query 学习率 2e-4、检测器学习率 5e-6，AdamW、cosine 调度；每两轮验证，保存最优验证损失与最新 checkpoint。
- 输出：`outputs/research/longterm_query_v6/pA/`。训练日志、history 和 checkpoint 均在该目录；没有覆盖 V5 输出。
- 已通过纯代码级连续帧运行，以及因果状态、跨序列重置和跨帧梯度测试。小规模运行仅排除实现错误，不用作性能结论。
- 实际 CenterPoint 三帧因果推理已通过。V6 入口已处理 OpenPCDet 数据辅助函数默认使用 `cuda:0` 的问题，可显式迁移到所选 GPU；该修复不改变已在 `cuda:0` 进行的正式训练。
- 待完整训练结束后，在相同五条留出序列比较 D0、D2、V5 attention v2、V6 开/关反馈的 AP@0.25/0.5、固定阈值召回、低分漏检恢复及原 GRAE 的 HOTA/DetA/AssA/IDF1/IDSW。固定分数阈值为 0.47854848529411764；GT 只用于正常监督与离线评估。

## 阶段判断

完整训练与推理评估未完成前，不宣称新网络改善 AP、HOTA 或弱目标召回。静态 ConvGRU 与 PAAF 联合训练待长期 Token 的独立贡献明确后再推进，避免同时改变多个因素而无法判断效果。

### 第 6 轮中期现象（非最终结论）

同权重开/关长期记忆：AP@0.25 为 `0.97957 / 0.97606`，AP@0.5 为 `0.94342 / 0.93977`，固定阈值 TP 为 `7607 / 7646`。开启反馈恢复了 148 个 D0 原漏检，但失去 186 个 D0 原正确检出；相对关闭反馈新增 84 个、失去 123 个。原 V5 attention v2 开启反馈恢复 119 个 D0 漏检，同时失去 187 个。V6 的净召回退化减小，但仍未消除。

经同一 GRAE 与官方阈值协议，V6 开/关的 HOTA 为 `0.71443 / 0.71828`，DetA 为 `0.68445 / 0.68524`，AssA 为 `0.75084 / 0.75784`；原 D0 HOTA 为 `0.72593`。此时 AP 改善没有转化为跟踪改善。开反馈的平均路由权重约 `0.8408`，BEV 反馈 RMS 约 `8.4%`，说明当前路由仍容易过度开启，额外误检是主要风险。第 6 轮中期对照脚本曾误指向 D2 的非 0.2 权重目录，因此该次 D2 行不使用；最终评估已改为 V4 的 `pA_D2_motion_w020`。

### 证据驱动的 V7 可靠性修订

`src/inframot3d/perception/reliable_query_feedback.py` 继承相同长期 Token 与在线 Query Bank，但增加当前帧预检测：用预测 Query 附近、同类别当前候选的置信支持度替代无法直接表征检测可靠性的局部特征强度。训练时在 GT 匹配成立且当前支持弱时监督打开历史路由，错误 Query 与清晰目标则监督关闭；对当前帧已清楚检出的 GT 热力图位置施加不下降约束。GT 不用于推理，最终检测和 Query 更新仍来自模型自身预测。这是基于中期误检现象的结构性改进假设，不是已验证性能提升。

V7 的双前向训练链路曾暴露 OpenPCDet CenterHead 目标分配对 GT 类别索引的原位改写；现为预检测与最终检测分别提供克隆的 GT 张量。修复前的异常损失不纳入实验，修复后代码级连续帧训练与三帧在线推理均通过。完整 V7 训练应在 V6 最终模型确认后接续。
