# 运动检索改进实验

本轮只做离线检索、预测对照和困难关联诊断，没有修改正式 GRAE 在线跟踪器，也没有训练知识融合网络。官方 val 未参与建库和参数选择。指标以轨迹宏平均为主，先对同一轨迹的窗口取平均，再对轨迹取平均。

## 和 R39 的差异

R39 的 Key 是 1 秒内 5 个点加路径长度速度，检索分是位置、形状和朝向的乘积，默认半径 25 m，并有最低分。它的 Value 存在 0.5 到 2 秒四个点。当前公开评估里的 Top-5 Oracle 用未来 ADE 选整条候选，minFDE@5 用 2 秒误差选整条候选，二者都不可部署。若再按每个时刻取不同候选的最小误差，会把多条轨迹拼成一条，仍然是 Oracle。

上一轮 InfraMOT3D 使用 11 点历史、60 m 范围、粗道路标签，并把 Top-K 不同转向直接平均。本轮把 Top-1、Top-K 平均、按模式平均、minADE@K、minFDE@K 和逐时刻最小分开报告。

## 采样检查

虚拟雷达帧间隔并不严格等于 0.1 s。用均匀 0.1 s 网格做最近邻时，历史窗重复采到同一帧 8548 次，未来窗重复 5975 次，未来点落到锚点及以前 107 次。这些窗口没有进入本轮知识库，也没有进入查询。

查询 9500 个窗口、232 条轨迹。查询侧重复历史 3753，未来重复采样 5818，未来点落到锚点及以前 263。60 m 基线覆盖率 0.959，Top-K 里与 Top-1 模式不一致的比例 0.383，候选终点标准差 2.732 m。残差实际触发比例 0.766。

HiVT 官方实现取前 50 个时间戳做历史，并以 AV 为中心，还依赖交通灯和协同轨迹。TNT 官方观测长度是 20 帧、预测 30 帧，地图是 Argoverse 或 TFD 矢量图。二者都不是 SPD 的 1 秒历史、2 秒未来和路侧折划分，也没有可直接套用的权重。本轮不训练新网络，因此不报告 HiVT 和 TNT 数值，只加入无需训练的 CTRV。

## 三个问题

1. 原 KV 的 2 秒轨迹 ADE 是 1.5608，同一批轨迹上的 CV 是 0.9086。5 点与 11 点几乎一样，10 m 和 25 m 比 60 m 更差，角速度和车道后继也没有拉近 CV。按 Top-1 的未来模式重新平均后是 1.5270，只比原平均 1.5608 略好，所以把不同转向平均在一起不是主要原因。始终加上 Top-1 残差是 1.0569，已经明显好于搬运绝对未来，但仍然差于 CV。整条 minADE@K 是 1.1240，逐时刻最小是 1.0792，二者都还高于 CV。因此被验证的原因是：检索到的绝对未来，包括 Top-5 里最好的一条，整体上仍不如当前目标自己的匀速；残差去掉了一部分速度误抄，但 Top-1 本身不够准。均匀 0.1 s 网格还会在不规则帧上重复采样，旧的 11 点并没有 11 个独立位置。

2. 带可靠性门控的 CV 残差在 2 秒全部轨迹上是 0.8837，CV 是 0.9059，触发比例 0.766。左转 1.6500 对 CV 1.8531，右转 1.8810 对 CV 2.2281，直行 1.0518 对 CV 1.0238，减速直行 1.3630 对 CV 1.4971。0.5 秒和 1 秒上残差是 0.2917、0.4371，CV 是 0.2689、0.4277，短时没有优势。残差只在转弯和减速上低于 CV，直行匀速段更差。无条件残差是 1.0569，不能在所有样本上替代 CV。CTRV 全部轨迹 ADE 是 0.9707，也没有稳定超过 CV。

3. 真实序列有正样本的时刻是 17816，GRAE 分配失败 21，身份切换 7。去掉 0066 后全体 Top-1 仍是 0.9995，正确距离中位数 0.1898 m，所以候选集合本身很简单。全体时刻上残差修正 3、新增错误 3，CV 修正 4、新增错误 4，原 KV 修正 1、新增错误 4。只看失败时刻时残差修正 3、CV 修正 4、原 KV 修正 1，但失败子集不含原本正确的样本，不能把新增错误算成 0。受控缺测里，0.3 秒恢复命中 GRAE 0.8232、CV 0.9242、原 KV 0.8434、残差 0.9293；0.5 秒是 0.6684、0.829、0.6736、0.829；1 秒是 0.4821、0.7262、0.4821、0.7262。残差与 CV 几乎相同，原 KV 几乎不改 GRAE。1 秒 Oracle 命中 0.9762，只说明真实位置还有余量，不能部署。运动知识降低了一部分位置误差，没有让正确关联稳定胜过错误关联。
